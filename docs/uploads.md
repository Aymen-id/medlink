# Authorized document uploads

The browser sends only validated metadata to `POST /api/uploads`. PostgreSQL locks the physician workspace and atomically counts existing files plus pending unexpired reservations. A Free workspace can reserve at most ten total slots. Pro/Clinic entitlements come from the workspace's billing account. No direct patient-file INSERT policy is exposed to authenticated clients.

The browser uploads file bytes directly to the private Supabase bucket using its authenticated client and the exact reserved path. Files are limited to 50 MiB and the documented PDF, raster-image, text and Word MIME types. Overwrites are denied. Storage INSERT requires a live reservation owned by the requesting user. Patient and folder membership are checked in both the application and database.

`POST /api/uploads/:id` finalizes a reservation only when the stored object's size and MIME metadata match. Finalization is idempotent. It creates the file record and marks the reservation finalized together. Until that commit the object cannot be read. A failed upload requests cancellation, releases quota, and removes the object; if removal fails, cleanup remains queued. Unfinished reservations expire after ten minutes and no longer consume quota. Expired finalization is rejected even if it waited for a workspace lock.

`GET /api/uploads/cleanup` requires a server-only `CRON_SECRET` (at least 32 random characters). The prepared Vercel configuration invokes it daily, compatible with Hobby scheduling. Each invocation removes at most 500 expired/canceled objects and marks them cleaned only after Storage deletion succeeds. Failures return an error and stay eligible for retry. On higher-volume deployments, configure a more frequent schedule supported by the hosting plan and monitor the cleanup backlog. The schedule is not active until deployed with the secret configured.

Ordinary downloads use an authenticated application endpoint and revalidate membership for every request. Direct authenticated Storage SELECT is denied because that privilege also permits bearer-URL minting. The server first queries file metadata with the user's client/RLS, then reads only that authorized object's path with its admin Storage client. Cancellation likewise authorizes the reservation before privileged object cleanup. The historical `getSignedUrl` helper returns the local endpoint; it no longer creates hour-long bearer URLs that could survive membership revocation. Previously issued signed URLs cannot be retroactively invalidated by this code change and expire under their original TTL.

Local tests execute reservation/quota/finalization SQL on embedded PostgreSQL and exercise browser transport and cleanup with service mocks. They do not prove a real 50 MiB Storage upload, hosted metadata shape, multi-connection contention, physical orphan removal or deployed scheduler execution. Those remain service acceptance gates on the intended MediLink project.
