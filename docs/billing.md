# Billing reconciliation

Only billing_accounts.billing_admin_id can open Checkout or Portal for the selected workspace account. Provider membership or workspace ownership alone does not grant billing administration. Provider workspaces resolve entitlements through their billing_account_id. Staff membership still requires Clinic.

A database lease serializes app-initiated billing and webhooks per account. Customer creation uses a stable idempotency key, and the customer ID is durably bound before Checkout. Repeated requests reuse an open session for the same price and expire other open sessions. Existing nonterminal subscriptions always use Stripe Portal's subscription_update_confirm flow, including monthly/annual changes; the app does not purchase a second subscription. Configure Portal products/prices and update confirmation in the intended Stripe test environment before acceptance.

Webhook signatures are required. Subscription lifecycle events, Checkout completion/async success and invoice paid/payment-failed events trigger reconciliation. The handler takes the account lease before fetching canonical Stripe subscription state. This avoids applying stale event snapshots in delivery order. State and event receipt are persisted in one transaction, guarded by the lease token. A persistence error returns 503 and does not record success, allowing Stripe to retry. Duplicate event IDs are idempotent. Canceled or expired subscriptions and non-active/non-trialing status grant Free entitlements. Unrecognized prices and multiple active subscriptions require reconciliation rather than silently granting a paid tier.

The lease lasts 120 seconds, renews before Checkout mutations, and rejects stale writes. Stripe requests have a 20-second timeout and one network retry. Multi-process contention and real Stripe network failure behavior remain service acceptance gates. The existing Stripe API version is retained to preserve service configuration; SDK/API upgrades require their own compatibility verification.

Provider acceptance now coordinates with personal billing: a service-held lease checks canonical Stripe subscriptions, expires open Checkout sessions, rechecks subscriptions, and durably freezes new purchases before the authenticated acceptance RPC moves the workspace. Direct RPC acceptance rejects an active personal lease, unresolved Stripe customer or nonterminal obligation. Checkout checks account eligibility under its lease and again before issuing a newly created URL; if eligibility was lost, that unissued session is expired. A failed acceptance unfreezes only a still-owned personal workspace. Returning to the personal account restores purchase eligibility.

A Clinic downgrade or loss of active coverage restores additional providers to their personal billing accounts when the subscription snapshot is persisted. Their patient ownership and records remain unchanged; Pro coverage applies only to the billing administrator's workspace. Entitlement checks also treat uncovered extra workspaces as Free even before a delayed reconciliation arrives. Existing files remain readable; finalization rechecks the current Free cap under account/workspace locks. The passage of a subscription period without webhook delivery still requires operational reconciliation and service acceptance.

Required server settings: STRIPE_SECRET_KEY (a least-privilege restricted test key is preferable where supported), STRIPE_WEBHOOK_SECRET and all four STRIPE_PRICE_PRO_MONTHLY/PRO_ANNUAL/CLINIC_MONTHLY/CLINIC_ANNUAL values. Do not use live-mode credentials for synthetic acceptance. No automatic_tax settings were enabled; tax registration and billing configuration require review before launch.

Local SQL and mocks cover billing-admin denial, canonical state, duplicate deliveries, persistence failure/retry, payment failure/cancellation, customer/session reuse, annual price selection and error recovery. They do not prove a Stripe test-mode purchase, Portal configuration or hosted webhook delivery.

References: https://docs.stripe.com/webhooks and https://docs.stripe.com/customer-management/portal-deep-links .
